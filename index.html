How I build

Three design decisions and three lessons from the operations data platform. Full write-ups on GitHub.

Decisions I will defend

  1. Calculate scores on request. Do not save them.

    A saved health score became false when its data changed. I deleted the feature, although people liked it. Now the system saves raw numbers and calculates the score when a person asks.

  2. Only one service can write data.

    The service that the AI model uses is read-only. If a number is wrong, only one part of the code can be the cause. Bad model output cannot change the records.

  3. New tools are locked by default.

    Only the highest role can use a new tool until a person gives wider access. If someone forgets, nobody can use the tool. That is safer than everybody using it.

Lessons from production failures

  1. Alert on silence, not only on errors.

    An expired credential stopped all scheduled jobs for weeks. Nothing ran, so nothing logged an error. Now I alert when a job does not report.

  2. Test the path that real users take.

    I tested a sign-in fix with a service key. Users signed in another way, and the fix did not work for them. Now I test each fix on the real user path.

  3. Make rules executable.

    A comment said "keep these two values the same". Nobody read it, and a job stopped for two weeks. Now a test fails the build when the values do not agree.
